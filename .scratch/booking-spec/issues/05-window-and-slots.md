# 05: Зафиксировать 14-дневное окно и генерацию слотов

Type: grilling
Status: resolved
Blocked by: 02

## Question

Как считать 14-дневное окно и генерировать слоты для выбранного типа встречи?

Решить:

- якорь «сегодня» в Europe/Moscow и границы 14 календарных дней включительно;
- отбрасывание прошедших слотов сегодняшнего дня;
- рабочие дни Пн–Пт, часы 09:00–18:00, шаг стартов 30 минут;
- условие валидности слота: `start + duration <= 18:00`, где duration берётся из типа встречи;
- как занятые бронирования всех типов исключают слоты и как разрешено примыкание;
- что возвращать для дня без слотов: пустой день или отсутствие дня;
- формат времени в API и UI: UTC ISO или локальное время с offset; как не сломаться на переходе суток;
- нужна ли отдельная операция «доступность по дню» или достаточно одного запроса на 14 дней.

Связанные тикеты: «Исследовать SQLite и работу с часовыми поясами», «Зафиксировать правило занятости и защиту от одновременных бронирований», «Спроектировать публичный сценарий гостя», «Согласовать API-контракт в TypeSpec». Формат — `grilling` + `domain-modeling`.

## Answer

### Якорь и границы окна

- «Сегодня» — `now.setZone('Europe/Moscow').startOf('day')`, где `now` передаётся через инъекцию часов.
- Окно — 14 календарных дней со смещениями `0..13` от сегодняшнего дня.
- Если сегодня 15 ноября, окно — 15–28 ноября включительно.
- Выходные входят в окно как дни с пустым списком слотов.
- Сегодняшний день остаётся в окне, даже если после 18:00 слотов уже нет.
- Серверная локальная зона не используется.

Календарные дни считаются через `startOf('day')` и `plus({ days: 1 })`, а не прибавлением 24 часов к timestamp. Это защищает от DST и смены зоны сервера, хотя у Москвы сейчас постоянный UTC+3.

### Прошедшие слоты

- Слот доступен, только если `start > now` (строгое неравенство).
- Слот, начинающийся ровно «сейчас», недоступен.
- Прошедшие слоты сегодняшнего дня не возвращаются.
- Окно не прокручивается на следующий день, если сегодня слотов не осталось.
- После 18:00 сегодняшний день присутствует в ответе с `slots: []`.
- Та же проверка `start > now` выполняется при создании бронирования, а не только при выдаче доступности.

Если сейчас 12:00:00, слот 12:00 недоступен; если 08:59:59, слот 09:00 доступен.

### Генерация слотов

- Рабочие дни — Пн–Пт (`weekday` 1–5 в московской зоне).
- Первый возможный старт — 09:00, последний зависит от длительности.
- Старты идут по сетке `09:00 + n * 30` минут.
- Условие валидности — `start + duration <= 18:00`, где `duration` берётся из типа встречи.
- Длительность не обязана быть кратной 30: шаг относится только к стартам.
- Встреча, заканчивающаяся ровно в 18:00, валидна.
- Встреча 09:00–18:00 при длительности 540 минут валидна и занимает весь день.

Последние старты:

| Длительность | Последний старт |
| --- | --- |
| 30 минут | 17:30 |
| 45 минут | 17:00 (конец 17:45) |
| 60 минут | 17:00 |
| 540 минут | 09:00 |

Сетка строится от 09:00 в московском времени, а не от полуночи UTC. Используются константы домена из тикета 03: `WORK_START_MIN = 540`, `WORK_END_MIN = 1080`, `SLOT_STEP_MIN = 30`, `WINDOW_DAYS = 14`.

Алгоритм:

```ts
const ZONE = 'Europe/Moscow';
const today = now.setZone(ZONE).startOf('day');

for (let offset = 0; offset < WINDOW_DAYS; offset++) {
  const day = today.plus({ days: offset });
  const slots = [];

  if (day.weekday >= 1 && day.weekday <= 5) {
    for (let m = WORK_START_MIN; m + durationMin <= WORK_END_MIN; m += SLOT_STEP_MIN) {
      const start = day.plus({ minutes: m });
      const end = start.plus({ minutes: durationMin });

      if (start <= now) continue;
      if (busy.some((b) => b.startMs < end.toMillis() && b.endMs > start.toMillis())) continue;

      slots.push({ start: start.toUTC().toISO(), end: end.toUTC().toISO() });
    }
  }

  days.push({ date: day.toISODate(), slots });
}
```

### Исключение занятых слотов

Запрашиваются все интервалы, пересекающиеся с окном:

```sql
SELECT start_ms, end_ms
FROM bookings
WHERE start_ms < @windowEndMs
  AND end_ms > @windowStartMs
```

- Фильтра по типу встречи нет: занятость глобальная.
- Для каждого кандидата проверяются полуинтервалы тем же предикатом `b.start_ms < slotEndMs AND b.end_ms > slotStartMs`.
- Примыкание разрешено: занятие 10:00–11:00 не исключает слот 09:30–10:00 или 11:00–11:30.
- Доступность читается без `BEGIN IMMEDIATE`: это read-only запрос, writer-лок не нужен.
- Список слотов актуален на момент запроса. Если слот забронируют сразу после ответа, авторитетна транзакция бронирования из тикета 04; гость получит `409`.
- В ответе доступности нет имён, email и комментариев гостей — только свободные интервалы.

Индекс `(start_ms, end_ms)` покрывает запрос окна. Отдельная материализация слотов не нужна: слоты вычисляются на каждый запрос.

### Формат ответа и одна операция

- Один запрос доступности для выбранного типа встречи возвращает всё 14-дневное окно; отдельной операции «доступность по дню» нет.
- Ответ содержит ровно 14 элементов, отсортированных по возрастанию даты.
- Каждый день — `{ date, slots }`, где `date` — календарная дата в `Europe/Moscow` (`YYYY-MM-DD`).
- Пустые дни и выходные присутствуют с `slots: []`, а не исчезают из ответа.
- Каждый слот содержит `start` и `end` в ISO 8601 UTC с `Z`.
- Локальное время без offset не передаётся; UI форматирует UTC-инстанты в `Europe/Moscow` явно.
- Группировка по дням идёт по московской дате, а не по UTC-дате.
- Если тип встречи не найден — `404`; если типов нет, публичный список пуст и доступность не запрашивается.
- Точные имена полей, наличие `timeZone` в ответе и путь операции финализирует тикет 08.

Максимум около 14 × 18 = 252 слотов, поэтому один запрос дешевле и проще для UI, чем 14 запросов. Кэширование не нужно.

### Тесты

- `now` — понедельник 08:00 MSK → первый слот сегодня 09:00.
- `now` — понедельник 12:15 → первый слот 12:30.
- `now` ровно 12:00 → слот 12:00 отсутствует.
- `now` после 18:00 → сегодня `slots: []`, следующие дни нормальные.
- Суббота и воскресенье → пустые дни.
- 14-й день присутствует, 15-й отсутствует.
- Последние старты для 30, 45, 60 и 540 минут.
- Занятость 10:00–11:00: слоты 09:30–10:00 и 11:00–11:30 остаются, 10:00–10:30 и 10:30–11:00 исчезают.
- Бронь другого типа встречи тоже исключает слот.
- Весь день занят → пустой день.
- «Сейчас» около полуночи MSK: `2026-11-15T00:30+03:00` даёт якорь 15 ноября, а не 14-е по UTC.
- Тесты гоняются с `TZ=UTC` и, желательно, с другой системной зоной, чтобы поймать случайное использование локального времени.
- Интеграционный тест запроса занятости из SQLite и API-тест формы 14-дневного ответа.
- После успешного бронирования повторный запрос доступности не содержит занятый слот.

Основная логика `buildSlots(now, durationMin, busyIntervals)` тестируется юнит-тестами с фиксированным `now`; SQLite и API проверяются отдельно.

### Глоссарий

- **Окно записи** — скользящий период из 14 календарных дней, начиная с текущей даты в `Europe/Moscow`, в котором гость может выбрать слот.
- **Доступность** — набор свободных слотов в окне записи для выбранного типа встречи.
