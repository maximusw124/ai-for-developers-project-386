# Архивирование типов встреч вместо физического удаления

Типы встреч не удаляются физически: в `meeting_types` добавляется nullable `archived_at_ms`. Архивирование скрывает тип из публичной записи и запрещает новые бронирования, но сохраняет строку для уже созданных встреч. Это позволяет убрать тип из публичного списка даже после первой брони, не нарушая `ON DELETE RESTRICT` и не теряя историю.

Альтернативы — запрет удаления при наличии бронирований и снимок названия/длительности в каждом бронировании — либо не дают убрать использованный тип, либо усложняют модель. Физическое удаление и каскадное удаление отклонены: они уничтожают контекст предстоящих встреч.

## Consequences

Публичные запросы списка типов и доступности фильтруют `archived_at_ms IS NULL`; создание брони для архивного типа возвращает `404`. Существующие бронирования и их интервалы не меняются. В админке архивные типы видны отдельно, доступны только для восстановления и не редактируются. Физическая очистка архивных типов в первой итерации не поддерживается.
